Tiiny Image Agency — Architecture

Plan → resolve → load → generate → critique, with an NPU residency manager in the middle. Facts read from the device 2026-11-06.

The loop

  • • Planner → requirement vector, never a model name
  • • Resolver → deterministic model pick + a paragraph explaining it
  • • Dialect translator rewrites intent for the target model
  • • Critic judges the prompt against the vector, not the user's words
  • • Retry bound: 3 generations per user turn

Residency arithmetic

  • • NPU pool: 47.9 GiB, one shared pool, evicting
  • • The hot path is planner (55%) + image model (23%) = 78%
  • • 85% is admitted and then refused — 150004
  • • Qwen-Image-2.1 at 62% + planner at 55% = 117% — swap
  • • The flagship runs alone: the planner is released and restored
  • • Percentages are the device's claim — measure before trusting

Four traps, all closed

  • • TTY: tiiny load needs a pty — script -q /dev/null
  • • Watchdog: re-loads its set every 5 min — the hold is written before the load
  • • Replay: the event bus replays to late subscribers, so every consumer filters by job_id
  • • Dimensions: a judge's change is an instruction — a request for the size is dropped
  • • The bearer is device-admin grade — the adapter only, never in a response or a log

Why the registry is three layers

  • • Device facts — read live from /api/v1/models/online_models; they move
  • • Specialty overlay — hand-curated: what each model is good at, which dialect it wants
  • • Research cards — measured on the appliance by probing it, because the device's own desc is wrong for at least one model
  • • A model that is listed is not a model that is downloaded — the resolver will not pick one that is not on disk

One rule

  • • Agents do not bypass the orchestrator
  • • A direct call to /v1/images/generations evicts the chat model and the caller will not know what it displaced
  • • The API exists so that never happens
  • • The CLI and the skill are HTTP clients of the API, so neither can hold the appliance

The two surfaces

  • • CLI — an HTTP client of the API. It holds no credential and cannot reach the device
  • • Work surface — three static files, no build step, served from the API's own port
  • • The skill — the procedure an agent follows, and it names the CLI commands
  • • The surface shows the model badge, the NPU meter and the swap banner, because the constraint should be visible
